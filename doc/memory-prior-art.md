# 记忆系统的计算机史参照：OS / 数据库 / 数据结构 / AI

> 2026-10-26。目的：把「Agent 记忆」放回计算机史的坐标系，找已被验证过的解法，
> 并标注本项目哪些已用（✅）、哪些试过无效（✖）、哪些未做（☐）。
> 数据出处见 README §十五–§十七、§14.1。

核心观察：**Agent 记忆 = 容量受限的上下文（快存储）+ 无限增长的历史（慢存储）之间的调度问题**。
这和 OS 内存管理、数据库缓冲池、CPU 缓存是同一类问题，只是「页」换成了「一条记忆」，
「缺页代价」换成了「答错」。

---

## 一、操作系统：存储层级与分页

| OS 概念 | 记忆系统对应 | 本项目 |
|---|---|---|
| 存储层级（寄存器→Cache→RAM→磁盘） | 上下文窗口 = RAM；记忆库 = 磁盘；Search = 调页 | ✅ Answer 上下文 117,760 token 即"物理内存"，`budget.clip` 按 token/字节预算装页 |
| 虚拟内存 / 按需分页 | 不全塞上下文，按需取回（MemGPT 2023 直接借用此隐喻） | ✅ Add/Search 契约本身 |
| 工作集模型（Denning 1968） | 任务只需小工作集；装太多会颠簸（thrashing） | ✅ B2 实测：答案在 top 10–20 饱和，top 100 反降（TTL EM 0.33→0.17）= 颠簸 |
| Belady 最优置换（1966） | 预知未来的理论上限 | ✅ `e2e_proxy --oracle` 即 Belady 上限：EM 0.535 vs 实际 0.342 |
| LRU / LFU / ARC（2003） | 遗忘/淘汰策略 | ☐ 竞赛库小不需淘汰；产品化必需（ARC 兼顾"最近"和"常用"） |
| 局部性原理 | 时间局部性 = 新近更相关；空间局部性 = 相邻轮次一起有用 | ✖ 新鲜度规则（KR −0.033）、相邻上下文向量（split b 0.761→0.709）均默认关 |
| 预取（prefetch） | 预测下一问需要的记忆 | ☐ 评测是独立问题，收益小 |
| 页大小选择 | 记忆粒度：按轮 / 按会话 / 按事实 | ✅ 按消息存、长文本 `split_text` 切段 |

**启示**：工作集和 Belady 两个概念给了我们两把尺子——
「返回多少条」由工作集决定（不是越多越好），「检索还有多少空间」由 Belady 上限决定。

## 二、数据库：版本、时间、更新

| 概念 | 记忆系统对应 | 本项目 |
|---|---|---|
| MVCC / 多版本 | 同一事实多个版本，默认读最新 | ✅ 同分 tie-break `created_at desc` |
| LSM 树（O'Neil 1996） | 追加写 + 读时新覆盖旧 + 后台 compaction | ✅ Add 只追加；☐ compaction（旧事实标 superseded）未做 |
| 双时态数据（SQL:2011） | 有效时间（事情何时发生）vs 事务时间（何时被告知） | ⚠️ 已有 `ts` 与 `created_at` 两字段，未作为两条时间轴分别查询。TR/KR 题正需要它 |
| 查询优化器 | 不同查询走不同访问路径 | ☐ **= 证据集形状问题**：数图题应走「按日期聚合图片」而不是语义 top-k |
| 物化视图 | 预计算聚合 | ☐ Add 时维护「每天几张图、各是什么主题」，直接服务 VR/VS/TTL |
| 幂等 / WAL | 重试不重复写 | ✅ `request_id` 幂等表、SQLite WAL |
| 缓冲池 | 热数据常驻内存 | ✅ `_USER_CACHE`（LRU，按字节限额）、检索索引缓存 |

## 三、数据结构与算法

| 算法 | 用途 | 本项目 |
|---|---|---|
| 倒排索引 + TF-IDF / BM25 | 关键词检索 | ✅ 稀疏通道（β=0.05，SPARSE_NORM=sat） |
| HNSW / IVF-PQ / LSH | 近似最近邻 | ☐ 每用户几千条，暴力精确更快且可复现，不需要 |
| MinHash / SimHash（1997 / 2002） | 近重复检测 | ✅ 余弦 ≥ 0.97 + 文本指纹去重 |
| 内容寻址（git） | 内容哈希即身份 | ✅ `img_sig`、确定性 `det_id`、caption 缓存键 |
| 布隆过滤器（1970） | 快速判断"一定没有" | ☐ 对应 AR 拒答题：先判「此事从未提及」 |
| 区间树 / 线段树 | 时间范围查询 | ☐ 「6 月到 7 月间…」类问题 |
| MMR（Carbonell 1998） | 相关性与多样性平衡 | ✖ λ=0.05/0.15 互有胜负，`DIVERSITY=0` |
| RRF（Cormack 2009） | 多路排序融合 | ✅ 可选 `FUSION=rrf`；默认线性融合更好 |
| 两阶段检索（召回→精排） | 粗排宽、精排准 | ✅ 有 `qwen3-rerank`；答案端无可测收益，默认关 |

## 四、人工智能 / 认知科学

| 概念 | 对应 | 本项目 |
|---|---|---|
| 真值维护系统 TMS（Doyle 1979） | 新事实推翻旧结论时，依赖旧事实的结论一并失效 | ☐ 对应 CD 矛盾题 |
| 基于案例推理 CBR（Aamodt & Plaza 1994）：Retrieve–Reuse–Revise–Retain | 记忆系统完整循环 | 部分：只做了 Retrieve + Retain |
| 分代垃圾回收（Ungar 1984）："多数对象早死" | 闲聊多数很快无用，存活的才晋升长期区 | ☐ |
| Atkinson–Shiffrin 记忆模型（1968） | 感觉 → 短期 → 巩固 → 长期 | ☐ 写入时摘要/抽取（开源榜 Add 侧只许 `gpt-4o-mini`，且受可复现约束） |
| 遗忘曲线（Ebbinghaus 1885） | 记忆强度随时间衰减、复习强化 | ✖ 线性新鲜度已证无效；评测题不偏向新近 |

## 五、对本项目的可执行映射

按 oracle 诊断的显著差距排序（README §16.1）：

| 优先 | 参照 | 做法 | 目标题型 | 理论空间 |
|---|---|---|---|---|
| 1 | 查询优化器 + 物化视图 | Add 时按日期/会话建图片聚合；Search 识别「数/选图」类问题，改用聚合路径并收窄证据集 | VR / VS / TTL（48% 题量） | oracle EM +0.28～+0.44 |
| 2 | 双时态 + LSM compaction | 新事实写入时把同主体旧事实标 superseded；查询区分发生时间与告知时间 | KR / CD / TR | 小（oracle 不显著） |
| 3 | 布隆过滤器式否定判断 | 先判主体是否出现过，未出现则返回极少证据 | AR | oracle EM +0.16 |

**前提**：三项都改变「证据集形状」，只在评分 = Answer 输出时有益；
若评分基于 Search 返回条目，收窄会伤召回（`MAX_RESULTS=20` 时 R@100 0.70→0.35）。

## 六、已证伪的方向（防重踩）

| 参照 | 实验 | 结论 |
|---|---|---|
| 时间局部性（新鲜度加分） | `RECENCY_RULE=update` | split a KR −0.033，弃 |
| 空间局部性（相邻上下文入向量） | `EMBED_CONTEXT=1` | split b MRR 0.761→0.709，弃 |
| MMR 多样性 | `DIVERSITY=0.05/0.15` | 互有胜负，弃 |
| 低分阈值拒答 | top-1 分数 0.5 阈值 | AR/非 AR 分布重叠，净 −0.013 EM，弃 |
| 日期匹配加分 | `DATE_WEIGHT` | 仅命中 14/1,711 题，噪声内 |
| 精排 | `qwen3-rerank` | MRR +0.04，但答案端 ±0.02 无可测收益 |
