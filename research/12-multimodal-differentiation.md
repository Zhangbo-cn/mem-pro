# 12 · 多模态赛道的差异化：按官方三组能力重映射

- 生成时间：2026-10-14T06:50:00+08:00
- 决策：组别 = 开源方法榜；赛道 = **多模态记忆**
- 本次新增澄清：**顺序 = Search 之后的输出顺序（`data[]`，即 L1）**（用户，2026-10-14）
- 定位：本文件是 `08-differentiation.md`（按文本 A–H 组织）在**多模态能力体系**下的**替换版**；两者体系不同，不可混用

## 0. 摘要

1. **澄清带来的简化**：顺序 = `data[]`（L1）。因此**优化重心完全落在跨模态候选的 L1 统一排序**；条目内内容数组（L2）仍须正确解析，但不参与顺序评分。
2. **能力体系不同，必须重映射**：文本用 A–H 七项；多模态用**三组 / 14 子能力**（记忆认知 7、记忆演化 4、记忆对齐 3）。`08` 的论证不能直接沿用。
3. **多模态多出 6 个专属杠杆**（M1–M6），其中**最关键的两个**是：
   - **M1 跨模态分数校准** —— 文本与图像相似度**尺度不可比**，直接混排会产生系统性偏差，这是 L1 排序的**必要前置**；
   - **M2 表示冗余占位** —— 同一信息的原图 / OCR / caption 会各占一个 L1 位置，把真正不同的证据挤出前 k。
4. **最强落点**：**记忆对齐 → 证据治理**。因为**官方公告本身就要求参赛方声明**"是否使用原图、OCR、caption，以及是否返回图片证据"——这是唯一一处**平台明确要求你披露策略**的能力，因此形式化的"证据治理契约"（见 `11`）有天然的材料接口。

## 1. 澄清带来的设计含义

**用户澄清（2026-10-14）**：`顺序就是 search 之后的输出顺序`。

| 层 | 内容 | 是否参与顺序评分 | 仍需做什么 |
|---|---|---|---|
| **L1** | `data[]` 顶层数组顺序 | ✅ **是（唯一被评的顺序）** | **优化重点**：跨模态统一排序 |
| **L2** | 条目内 `content[]`（`text`/`image_url` 有序数组） | ❌ 否 | 仍须按规范正确解析（否则契约错误）；仍需承载"多模态写入/证据作答"要求 |

**简化后的设计重心**：

```
        ┌──────────── L1 排序（被评分）────────────┐
候选池 → 跨模态分数校准 → 去冗余 → 约束过滤 → 排序 → 截断 → data[]
        └──────────────────────────────────────────┘
                     唯一需要深度优化的环节
```

## 4. 多模态专属杠杆（M1–M6，`08` 中没有）

### M1 跨模态分数校准（**L1 排序的必要前置**）🔴

**问题**：文本向量（如 `text-embedding-v4`）与图像编码器产出的相似度**分布尺度不同**。直接合并后按原始分数排序，会出现系统性偏差——某一模态的分数整体偏高，独占 L1 前列。

**这是 L1 排序最容易被忽略、却最先致命的一步**：分数没校准，后面的排序策略再好都是在错误输入上优化。

**三条路径（按推荐度）**：

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **① 统一跨模态重排器**（推荐） | 对合并后的短名单（如前 20–50）用**单一跨模态打分器**重排 → 分数天然可比 | 分数尺度统一、可解释 | 需跨模态打分器；成本高于纯向量 |
| ② 分模态分位归一化 | 各模态内转分位数再合并 | 便宜、确定性强 | 破坏"分数可比"的语义；阈值难解释 |
| ③ 学习式融合 | 训练一个融合模型 | 上限高 | ⚠️ **AML 无金标**（✅不提供），且可解释性差 → 不作为主路径 |

**合规提示**：官方 ✅ `Reranker 不作限制` —— 这是模型选型中唯一放开的一环，**应优先用于此处的跨模态校准**。若情形 A 成立且需用 LLM 类打分器，`gpt-4o-mini` **原生支持图像输入** ✅，因此存在合规路径。

**可复现性要求**：若用 LLM 打分，必须 **pin 模型版本 + temperature 0 + 按内容哈希缓存**，否则破坏公榜准入的复现前提（`06` §七）。

### M2 表示冗余占位（**多模态特有的 L1 失效模式**）🔴

同一信息可能有三种表示：**原图**、**OCR 文本**、**caption**。若三者各占一条 L1 位置：

- 前 k 被同一份信息的 3 个副本占据 → **真正不同的证据被挤出**
- 位置预算被浪费（`10`：长度是负向变量）

**对策**：**表示合并（representation merging）** —— 同一事实的多种表示合并为 L1 的**一条**，把三种表示放进该条的 L2 `content[]` 内，并用 `modality_precedence` 声明内部采信序。

> 这也正好利用了 L1 / L2 的分工：**L1 表达"有哪几条不同的事实"，L2 表达"这条事实的多种表示"**。

### M3 跨模态可信度先验

`原图 > OCR 文本 > caption > 模型生成描述`

- 原图是**原始证据**；caption 可能是模型生成物（有幻觉风险）；OCR 是确定性派生但可能有识别错误
- 该先验在工程界普遍存在，但**极少被显式形式化** → 形式化本身就是可复用的差异化资产（`11` §5.2）
- ⚠️ 需场景声明可反转：例如**票据场景**中 OCR 文本可能比压缩后的图像更可靠

### M4 图文冲突消解（归入"知识更新"）

caption 说 A、图显示 B（或新图与旧图矛盾）→ 默认**以原图为事实源**，并把 caption 标记为"派生、次级"。
这相当于把 `11` 的 `authority` 属性**在跨模态下具体化**。

### M5 视觉事实的双时间轴

图片至少有三个时间：**拍摄/事件时间**、**写入时间**、**有效区间**（何时起代表"当前状态"）。
归入"时间推理"，是 `08` P1 包（双时间轴）的**多模态扩展**——视频帧/多图序列还会产生"顺序"语义。

### M6 无证据判定的难度上升（归入"拒答"）

文本下"无证据"≈检索为空。多模态下更微妙：**caption 有文字，但图与问题不相关** → 若因 caption 存在就返回，会污染 L1 并可能被判定为"把答案伪装成记忆"（官方红线 ✅）。
→ 需要**跨模态一致性判定**（图与文本是否指向同一事实）才敢决定返回或返回空。

## 5. 按能力分组的设计细节

### 5.1 记忆认知（7 子能力：检索、视觉推理、关系推理）

| 子能力 | 多模态下的具体挑战 | 差异化做法 |
|---|---|---|
| 检索 | 跨模态命中：文本 query → 图片证据；图片 query → 文本证据 | **M1 校准**后统一排序；双向召回 |
| 视觉推理 | 需要的细节**只在图里**，caption 已丢失 | **问题类型条件化的表示策略**：视觉型问题优先原图证据；事实型问题可优先文本 |
| 关系推理 | 图中实体 ↔ 文本实体的跨模态对齐 | 建立跨模态实体对齐（图像区域 ↔ 文本提及） |

> **M2 的表示选择**在此处最关键：若原图与 caption 都被召回，"给图还是给文"应**依问题类型决定**，而不是固定优先级。

### 5.2 记忆演化（4 子能力：时间推理、知识更新、持续学习）

| 子能力 | 差异化做法 |
|---|---|
| 时间推理 | **M5 双时间轴**（拍摄/事件时间、记录时间、有效区间）+ 视频/多图序列的顺序语义 |
| 知识更新 | **M4 图文冲突消解**（以原图为事实源）+ 旧图失效（`validity` 过滤） |
| 持续学习 | Streaming：写入即可检索；增量节点上的快照一致性（沿用 `05` 的同步语义） |
| （第 4 项） | ⚠️ 官方仅列出 3 个描述而称 4 个子能力 → **描述与计数不一致，待澄清** |

### 5.3 记忆对齐（3 子能力：个性化、拒答、证据治理）← **战略权重最高**

| 子能力 | 差异化做法 |
|---|---|
| 个性化 | 用户偏好（含**视觉偏好**：更接受图还是文）+ 敏感分级 + 最小披露 |
| 拒答 | **M6 跨模态一致性判定** → 敢返回空数组 `{"data": []}`（官方红线：不得把答案伪装成记忆 ✅） |
| **证据治理** | **`11` 的排序契约落地处**：证据优先序 + 过滤/排序两阶段 + 7 属性 Schema + 约束原语 + 确定性 tie-break + **模态使用声明** |

**为什么这里是最高价值落点**：
- ✅ 官方公告**本身要求**参赛方声明"是否使用原图、OCR、caption，以及是否返回图片证据" → **平台主动要你的治理策略**
- 因此"证据治理契约"不是自说自话，而是**直接对齐平台的披露要求**，在材料审核与复核中天然被阅读

## 6. 多模态特有的 L1 失效模式（汇总）

| # | 失效模式 | 后果 | 对策 |
|---|---|---|---|
| 1 | **跨模态分数不可比**（M1） | 单一模态独占 L1 前列 | 统一跨模态重排器 |
| 2 | **表示冗余占位**（M2） | 同一信息挤掉不同证据 | 表示合并（一事实一 L1 条目） |
| 3 | **caption 幻觉污染** | 生成描述被当作原始事实 | `modality_trust` 降权 + M4 冲突消解 |
| 4 | **无证据误判**（M6） | caption 有字就返回 → 触红线 | 跨模态一致性判定 |
| 5 | **图文跨模态对齐缺失** | 关系推理题召回不到对应证据 | 实体/区域级对齐 |

## 7. 属性 Schema 与约束原语在多模态的落点

承接 `11` §3.2 / §3.4：

| 通用组件 | 归属能力组 | 多模态下的具体化 |
|---|---|---|
| `validity` | 记忆演化 | 视觉事实的有效区间（M5） |
| `authority` | 记忆对齐 / 演化 | **M3 跨模态可信度先验**具体化 |
| `modality_trust` | 记忆认知 / 对齐 | M3；并影响 L2 内部采信序 |
| `specificity` | 记忆认知 | 直接证据 vs 间接相关 |
| `provenance` | 记忆对齐 | 原图/OCR/caption 的来源标注（平台要求声明） |
| `modality_precedence()` | 记忆对齐 | L2 内部序（原图 > OCR > caption） |
| `no_conflict_prefix(k)` | 记忆演化 | 图文冲突版本不得同时进前 k |
| `empty_if_no_evidence` | 记忆对齐 | M6 的前提 |
| `modality_balance(k)`（**新增**） | 记忆认知 | 限制单一模态在前 k 的占比上限（反 M1 偏差） |
| `dedup_representation()`（**新增**） | 记忆认知 | M2 表示合并 |

> 相比 `11`，多模态新增两个约束原语（`modality_balance`、`dedup_representation`）——这两个是**多模态特有**，文本下不存在。

## 8. 本地可测性（多模态代理指标）

⚠️ 官方 ✅ `不提供金标答案、评分依据或完整数据集下载`，且本地多模态替代基准少（`atm-bench`/`mem-gallery` 未在 arXiv 找到公开论文，判定为赛事自有基准）。故仍须自建代理评测：

| 手段 | 说明 |
|---|---|
| **合成图文对** | 自造"图-文-问"三元组，覆盖 M1–M6 六个失效模式各若干例 |
| **校准度量** | 测"各模态在前 k 的占比分布"是否均衡（可量化 M1 是否修好） |
| **冗余度量** | 测"同一事实的副本数 / 前 k 条目数"（可量化 M2） |
| **一致性度量** | 测"图文一致 vs 不一致"样本上的拒答准确率（可量化 M6） |
| **位置感知指标** | 沿用 `10` §6：首次命中位置、前 k 命中率、MRR、nDCG（全部基于 L1） |
| 契约测试 | 图文内容数组解析、`user_id` 隔离对抗测试（红线） |
