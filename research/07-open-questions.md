## 二、🔴 `text-embedding-v4` / `gpt-4o-mini` 约束的适用范围不明

| 疑问 | 说明 |
|---|---|
| **约束对象** | `LLM 相关组件须使用 gpt-4o-mini` —— "LLM 相关组件"具体包含哪些？写入侧抽取/摘要？重排？查询改写？图构建？平台侧 Answer 模型由平台固定 ✅ 应不在此列，但未被明确排除 |
| **Reranker 边界** | `Reranker 不作限制` ✅ 明确。但若用 LLM 做重排（LLM-as-reranker），是否算"LLM 组件"从而被锁 `gpt-4o-mini`？**未明确** |
| **多模态 Embedding** | FAQ 只锁定了 "Embedding 模型" 与 "LLM 相关组件"，**未提图像/多模态编码模型**。多模态赛道下图像向量该用什么？**未明确** → 这是多模态赛道最大合规风险 |
| **自训练模型** | `使用自训练模型或其他开放权重模型的系统，建议参加工业榜` —— 是"建议"还是"强制"？措辞为"建议"，但可能被审核解释为强制 |
| **本次处理** | 已按"保守分支"设计（默认 `text-embedding-v4` + `gpt-4o-mini`），并准备激进分支；列入待澄清 |

> 🆕 **2026-10-18 更新**：Evaluation Access 表单把撰写范围写到 **`any model used during Add **or Search** must be gpt-4o-mini`** —— 比 FAQ 05 的"LLM 相关组件"更宽。字面读会禁掉 reranker 与 embedding，但 FAQ 05 对这两者**有明确豁免**（`Reranker 不作限制`、Embedding 锁 `text-embedding-v4`）。
> → 落地解释：**除了这两项具名豁免，Add/Search 中任何生成式模型调用（抽取/摘要/caption/查询改写/LLM-as-reranker/拒答判定）都只能用 `gpt-4o-mini`**。
> → **图像编码模型仍无定义**，但两篇基准论文（`13` §3 E3）已证明图像向量不如文本检索，所以"全部转文本表示"既是合规定读也是最优解。

| **建议** | 以**阿里云百炼控制台/官方文档最新表格**为准；工程上按"每段 ≤ 2000 词"（官方规则 ✅）执行，天然低于任一上限，**不阻塞开发** |
