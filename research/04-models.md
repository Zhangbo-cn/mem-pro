## 二、Embedding 选型

### 2.1 `text-embedding-v4`（若约束生效则为唯一选择）

| 规格 | 值 | 来源 |
|---|---|---|
| 归属 | 阿里云百炼（Model Studio）／通义实验室，**Qwen3-Embedding 系列** | https://help.aliyun.com/zh/model-studio/embedding ✅ |
| 可选维度 | `2,048 / 1,536 / 1,024（默认）/ 768 / 512 / 256 / 128 / 64`（支持自定义） | 同上 ✅ |
| 单行最大 Token | ⚠️ **口径冲突**：一处写 `8,192`，另一处写 `33,000` | ⚠️ 同页不同表格，**未能确认**，列入 `07-open-questions.md` |
| 单次最大行数 | `10` | ✅ 同上 |
| 单价 | `0.0005 元 / 千输入 Token`；Batch 调用 `0.00025 元 / 千 Token` | ✅ 同上 |
| 语种 | `100+ 主流语种` 及多种编程语言 | ✅ 同上 |

- **API 兼容性**：支持 OpenAI 兼容接口；但 `output_type=sparse`（稀疏向量）**仅 DashScope 原生接口支持**，OpenAI 兼容模式下传入会返回 200 但 embedding 为空 ⚠️（来源：阿里云文档）。
- **对本项目的含义**：`text-embedding-v4` 是**闭源商业 API**。这与"开源方法榜"的字面语义存在张力——若该约束确实生效，则"开源"指的是**方法/仓库开放**，而非"全栈开放权重"。这是一条需要官方澄清的关键点。

## 三、Reranker 选型（FAQ 明确"不作限制" ✅）

官方原文：`Reranker 不作限制。` —— 这是模型选型中**唯一明确放开**的一环，应充分利用。

| 候选 | 规格 | 许可证 | 置信度 |
|---|---|---|---|
| **Qwen3-Reranker-0.6B / 4B / 8B** | 基于 Qwen3，**32K 上下文**，100+ 语言，支持任务指令 | Apache-2.0 | ⚠️ 来源于 web 检索（reranker.uk / MTEB-Code 汇总页），**HF 页未直连校验** |
| **BAAI/bge-reranker-v2-m3** | 基于 bge-m3，多语言，轻量易部署 | ⚠️ 未核实（HF 不可达） | ⚠️ web 检索称其为开源 reranker 强基线 |
| **gte-multilingual-reranker** | 多语言重排 | ⚠️ 未核实 | ❓ 未核实 |
| cross-encoder/ms-marco-MiniLM-L-6-v2 | 极轻量，延迟低 | ⚠️ 未核实 | ⚠️ 二手来源提及其为延迟敏感场景的平衡选择 |

**建议**：文本赛道选 `Qwen3-Reranker-4B`（Apache-2.0、32K 上下文覆盖长候选）或 `bge-reranker-v2-m3`（轻量）。Reranker 是**唯一能自主选择强模型的环节**，在 `top_k=100` 的场景下对最终顺序（即证据优先级 ✅）影响显著，应重点调优。

> ⚠️ 提醒：web 检索中出现的具体分数（如 Qwen3-Reranker 8B 的 MTEB-Code 分数）来自第三方汇总页，**未在本机独立复现**，不作为决策依据。

## 四、LLM 组件

### 4.1 `gpt-4o-mini`（若约束生效则为唯一选择）

| 规格 | 值 | 来源 |
|---|---|---|
| 上下文窗口 | `128,000` | https://developers.openai.com/api/docs/models/gpt-4o-mini ✅ |
| 最大输出 | `16,384` tokens | ✅ 同上 |
| 输入模态 | text, image | ✅ 同上 |
| 知识截止 | 2023-10-01 | ✅ 同上 |
| 默认快照 | `gpt-4o-mini-2024-07-18` | ✅ 同上 |
| 价格 | 输入 `$0.15 / 1M`，输出 `$0.60 / 1M`（缓存读 `$0.075 / 1M`） | ✅ 同上 + OpenAI 官方发布博客 ⚠️（页面 403，改由 developers 站与官方博客交叉确认） |

**关键推论（架构影响极大的地方）**：

1. `gpt-4o-mini` **支持图像输入** ✅ —— 这一点很重要：**即使 FAQ 05 的约束生效，多模态赛道仍可用它做图像理解**，不必额外引入视觉模型（但图像 embedding 仍需另外方案）。
2. 128K 上下文 + 16K 输出，对"写入侧做抽取/摘要"足够；但**写入 300M tokens 级数据时，LLM 调用成本与耗时是主要瓶颈**（见成本估算）。
3. ❓ **适用范围不明**：`LLM 相关组件须使用 gpt-4o-mini` 具体指什么？参赛方记忆系统内部的抽取/摘要/重排 LLM？还是也包含其他环节？平台侧的 Answer 模型由平台固定 ✅，应不在此列。**必须澄清**。

### 4.2 备选（仅约束不生效时）
- 任意开放权重小模型（如 Qwen3 系列）+ 本地部署；⚠️ 但 FAQ 明确"其他开放权重模型 → 建议参加工业榜"，与开源方法榜冲突。

## 五、结论：约束是否适用于「开源方法榜」？

### ✅ 直接回答：**官网未明确规定，两种情形都必须准备。**

| 情形 | 判定依据 | 约束是否生效 | 方案影响 |
|---|---|---|---|
| **情形 A**：`开源方法榜` ≡ FAQ 中的 `学术榜` | 语义上"开源/学术"对应"商业/工业"是最自然映射；且 FAQ 把"开放权重模型 → 工业榜" | **生效** | Embedding 锁死 `text-embedding-v4`；内部 LLM 锁死 `gpt-4o-mini`；仅 Reranker 自由 |
| **情形 B**：二者独立，FAQ 05 不适用于开源方法榜 | 官网从未把两个命名对应起来；组别名可能已更新而 FAQ 文案未同步 | **不生效** | Embedding/LLM 自由选型（可用开放权重） |

**官网直接证据**：赛事页与 `/rules` 全文使用「`开源方法榜` / `商业产品榜`」；FAQ 05 使用「`学术榜` / `工业榜`」。**两套命名在官网上同时存在，且从无交叉说明**（✅ 已逐页检索确认）。→ 属**真实口径冲突**，已列入 `07-open-questions.md` 并建议向 `contactus@agentmemoryleaderboard.ai` 书面澄清。

> ✅ **2026-10-18 结论更新（情形 A 成立）**：Evaluation Access 表单的 `Leaderboard track` 只有 `Academic leaderboard` / `Industry leaderboard` 两项，且写明 `For non-industry submissions, any model used during Add or Search must be gpt-4o-mini.`
> → **开源方法榜 ≡ 学术榜 ≡ 非工业**，且约束从 "expected to" 升级为 **must**、覆盖 **Add 与 Search 两侧**。
> → 本节下方"两种情形都要准备"的结论可以收敛为：**按情形 A 锁定方案**（`text-embedding-v4` + `gpt-4o-mini` + 自由 reranker），但把接口仍做成可替换——因为图像编码模型仍未定义。详见 `14-cycle2-site-recheck.md` §8。

### 两种情形下的推荐配置

| 环节 | 情形 A（约束生效） | 情形 B（约束不生效） |
|---|---|---|
| Embedding | **`text-embedding-v4`**（DashScope，维度取 1024 或 2048） | `text-embedding-v4`（若成本可接受）或 Qwen3-Embedding-4B 自部署 |
| Reranker | `Qwen3-Reranker-4B`（Apache-2.0）或 `bge-reranker-v2-m3` —— **两种情况都自由** ✅ | 同左 |
| 内部 LLM | **`gpt-4o-mini`**（写入侧抽取/摘要/冲突消解） | `gpt-4o-mini`（性价比仍优）或本地小模型 |
| 多模态编码 | ⚠️ 情形 A 下**多模态 embedding 无明确规定**（FAQ 只锁定 embedding 与 LLM）；可用 `gpt-4o-mini` 做 caption/图像理解 + `text-embedding-v4` 做文本向量 | 可用 Qwen-VL / CLIP 类开放权重 |
| OCR | 无约束，自由选型 | 同左 |

> **对赛道推荐的影响**：情形 A 下，**多模态赛道风险最高**（多模态 embedding 无官方指定，选型可能被判不合规），文本赛道受影响最小。这进一步支持 `01-track-differences.md` 的**文本赛道推荐**。

## 八、选型结论（一句话）

- **Reranker 自由** ✅ → 用最强开源 reranker（`Qwen3-Reranker-4B` / `bge-reranker-v2-m3`），因为 `top_k=100` 的输出顺序直接决定证据优先级。
- **Embedding 与内部 LLM 待澄清** ⚠️ → 默认按 `text-embedding-v4` + `gpt-4o-mini` 设计（保守），但把两者做成**可替换接口**，一旦官方澄清即可切换，避免返工。
- **多模态赛道在情形 A 下合规风险最高**，不作为首选。
