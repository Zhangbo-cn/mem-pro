## 0. 三句话结论

1. **情报已更新**：AML 多模态指定的两个基准 **ATM-Bench 与 Mem-Gallery 都有公开论文 + MIT 代码 + 可运行评测框架**。`02`/`07` 里"未找到公开论文、判定为赛事自有基准""本地自测信号弱"这两条**已被推翻**——本地复现是当前性价比最高的动作。
2. **方向必须落在三个旋钮上**（写什么 / 存什么 / 返回什么）。两篇论文的消融实验一致表明：**赢在"表示 + 选择性检索"，不在"架构"**。图记忆、全模态 embedding、答案侧 agentic 花招，三条路都已有**负向证据**。
3. **推荐主攻三个方向**：`D1 结构化记忆卡（SGM 式）` + `D4 自适应证据预算` + `D2 多表示合一`；`D6 证据簇`为上限押注，`D7 拒答阈值`为低成本加分，`D10 本地复现`为一切前提。**不做**图链接、不做全模态向量主检索、不做区域级 grounding。

## 2. 先把"方向"切对：平台只留给你三个旋钮

官方边界 ✅：`你只负责 Add / Search 环节。回答模型、提示词、评分器、数据集组合、Top K 和汇总规则由我们统一固定。`

因此**不存在"做产品"或"做算法"的路线之争**——所有方向最终都坍缩成同一个函数：

```
f(该 user 的记忆池, query) → data[]（有序，长度 ≤ top_k）
```

三个可动手的旋钮，其余全部不可动：

| 旋钮 | 内容 | 失手代价 | 文献证据强度 |
|---|---|---|---|
| **P｜表示（写什么）** | 每条记忆存成什么：自然语言描述 / 结构化键值 / 原图 / OCR / caption | 写入侧决定上限，检索侧无法弥补 | 🟢 **最强**（两篇各自独立证明） |
| **M｜组织与状态（存什么关系）** | 图链接 / 堆叠 / 时间状态 / 更新与失效 | ⚠️ **证据是负向的**：显式图链接不如简单堆叠 | 🟢 强（且是负向） |
| **R｜选择（返回什么）** | 条数、顺序、阈值、拒答 | 直接就是评分对象 | 🟢 强（K 效应 + 拒答 trade-off） |

> **不可动清单**（别浪费时间）：Answer 模型、评分器与提示词、Top K **上限** 100、题面与数据、评测流程。
> **可动但需合规**：embedding 与内部 LLM 选型（FAQ 05 未澄清，见 §9）、reranker（官方明确不限制 ✅）。

**这个切法带来的第一个反直觉结论**：多模态赛道里最值得投入的不是"更强的跨模态模型"，而是 **P 和 R**——因为 Answer 模型被平台固定，你能唯一改善的就是"喂给它的东西"。

## 3. 七条硬证据（决定方向取舍）

以下全部来自论文正文，标注出处；**这是本文与 `12` 最大的不同——`12` 是能力项映射，这里是消融实验结论**。

| # | 证据 | 原文关键点 | 对方向的含义 |
|---|---|---|---|
| **E1** | **SGM（结构化键值）> DM（自然语言描述），信息量完全相同** | ATM-Bench：Oracle 下 Hard 集 **+20%**；在 HippoRAG / Self-RAG / ATM-RAG 三种系统上，"SGM systems consistently achieves higher retrieval performance as well as higher downstream QS" | 🔴 **格式本身就是能力**。同样的信息换个格式就有增益 → 最便宜的分数来源 |
| **E2** | **Linked（图链接）< Piled（简单堆叠）** | ATM-Bench：把 A-Mem 改成 Piled 后"performance improves"，编码耗时 **12.6h → 1.6h** | 🔴 **图记忆是负收益**，且贵 8 倍。直接否掉 `12` 里偏架构的 M4/M5 重型路线 |
| **E3** | **多模态 embedding 反而不如文本 embedding** | ATM-Bench：`Qwen3-VL-Embedding-2B` 比文本 embedding 更差；原因推测"~2,500 visual tokens per image 稀释了 timestamp/location 等关键元数据" | 🔴 **不要用图像向量做主检索**。这同时把 FAQ 05 的 `text-embedding-v4` 约束从"风险"变成"**恰好对齐最优解**" |
| **E4** | **原图硬塞有害，但有组织的图文保留有益** | Mem-Gallery：Full Memory(MM) 比 Full Memory(Text) 差 **8.08%**、比 MuRAG 差 **51.85%**；而"简单保留多模态信息"的 MuRAG 综合最佳，比最好的文本记忆 **+11.85%** 总体 F1（VS +12.29%、TTL +29.06%），并胜过结构化的 NGM（+4.11%）与 AUGUSTUS（+5.39%） | 🟡 关键不是"要不要图"，而是**一条记忆里放什么、放几条** |
| **E5** | **K 越大越差（超过中等 K 后）** | Mem-Gallery：K 增大时 Recall 上升但 **Precision 骤降**；"diminishing or saturated task gains beyond a moderate K, and may degrade at larger K" | 🔴 **返回 100 条大概率是最差策略**。AML 只规定"不得超过 top_k"，**没规定必须等于** |
| **E6** | **拒答与召回是真实 trade-off** | Mem-Gallery：弱记忆的 FIFO 在拒答（AR）上反而最好，"A-Mem and MuRAG, with 7.22% and 5.82% worse F1 than FIFO" | 🟠 拒答需要**独立阈值**，不能靠"检索不到就拒答"顺带获得 |
| **E7** | **证据集很小，但预算被设成 100** | Mem-Gallery 平均 2.69 条 clue；ATM-Bench 主集 1.6 条 / Hard 6.3 条；两篇的默认检索预算都是 **k=10** | 🔴 典型错配：用 100 个位置的预算去装 2–6 条证据 |

### 3.1 由此**证伪**的方向（不要再做）

| 被证伪 | 证据 | 结论 |
|---|---|---|
| 图记忆 / 知识图谱链接记忆 | E2 | 更差且慢 8 倍。**不做** |
| 多模态（图像）向量作为主检索通道 | E3 | 不如文本检索，且贵。**不做**（但图像向量可作辅助/重排特征） |
| 复杂多模态记忆架构（NGM / AUGUSTUS 式） | E4 | 输给最简单的 MuRAG。**不做** |
| 答案侧 agentic / 自我反思 / 多轮改写 | ATM-Bench：`agentic answerer yields mixed gains`，Hard 集不迁移；**且 AML 的 Answer 由平台固定** | **完全无效**。不做 |
| 大规模 caption 生成后再检索（"描述式记忆"） | E1（DM 就是这条路） | 被 SGM 支配。**降级为基线** |
| 端到端训练 / 微调 | 官方 ✅`评测数据…不得用于模型训练、微调`；且只有 1 次 Full | **红线 + 不可行** |

## 4. 候选方向枚举与逐项评估

分层呈现：**P（表示）→ R（选择）→ G（治理）→ X（使能与材料）**。每个方向给"机制 / 证据 / 预期增益 / 工程量 / 风险"。

### P 层：表示（写入侧，决定上限）

#### D1 结构化记忆卡（SGM 式）｜**推荐 · 主攻**

- **机制**：每条记忆不存"一段自然语言描述"，而是存**固定 schema 的键值卡**，再把它拼成一段结构化文本用于检索：
  ```
  { id, t_event, t_record, place{gps,name}, source, modality,
    entities[], ocr, caption, tags[], state, valid_from, valid_to,
    supersedes, confidence, raw_ref }
  ```
  检索对象 = 结构化文本（时间/地点/实体/OCR/tag 全部参与），**不是裸 caption**。
- **证据**：E1（同信息 +20%）、E3（文本空间检索最有效）、E4（"有组织地保留"优于"堆原图"）。
- **预期增益**：**最高**。这是唯一有"同信息、只改格式、增益已被独立复现"的方向，且同时改善检索与 QA 两侧指标。
- **工程量**：中（字段设计 + 写入抽取 pipeline + 检索文本模板）。**不需要新模型**——用 FAQ 05 允许的 `gpt-4o-mini` 做抽取即可。
- **风险**：抽取质量决定上限；schema 一旦写死，回改成本高 → **先固定 10–12 个字段，不要扩张**。
- **判据**：本地 ATM-Bench 上 SGM vs DM 的 Recall@10 与 Joint@10 复现出正增益。

#### D2 多表示合一（一事实一卡）｜**推荐 · 必做**

- **机制**：同一事实的 原图 / OCR / caption **合并为一条 L1 条目**，三种表示塞进该条的 `content[]`，并在内部声明采信序（原图 > OCR > caption）。
- **证据**：E4（Full Memory(MM) 因视觉噪声与 token 挤占而更差）、E5（Precision 骤降来自噪声条目）、E7（预算只有 2–6 条）。
- **预期增益**：中高。直接减少"同一信息占 3 个位置"的浪费。
- **工程量**：小（写入侧去重 + content 数组组装）。
- **风险**：**合并过度会丢证据**——若两图细节不同（例如两张不同角度的同一张票据），合并会损失视觉证据。需按"是否同一事实"判定，而非按"同一实体"。
- **判据**：前 10 条中"同一事实副本数"从 ≥2 降到 1，且 Recall@10 不下降。

#### D3 原图保真策略（何时返回图、何时只返回文）｜**推荐 · 低成本高信息量**

- **机制**：不一律返回 `image_url`，按问题类型决定证据形态：视觉型问题 → 原图 + 结构化文本；事实/数值型 → 结构化文本（含 OCR）为主，图作为附带。
- **证据**：E3（视觉 token 稀释元数据）、E4（裸原图有害）、以及官方 ✅`平台保留图片内容并进入统一 Answer 链路`（即图确实会被使用，但不是非用不可）。
- **争议点** ❓：如果统一 Answer 模型视觉能力弱（如 `gpt-4o-mini`），返回图可能只增加 token 不增加信息。**这是必须本地自测的第一件事**（见 §9.2 实验 A）。
- **工程量**：小（策略开关 + A/B）。
- **风险**：判错题类型会反向丢分 → 默认"图文都给"，只在本地实验证明"图有害"的类别上关掉。

### R 层：选择（返回什么，直接评分）

#### D4 自适应证据预算（K 校准 + 分级返回）｜**推荐 · 主攻**

- **机制**：三件事——
  1. **估计必要证据数**（单证据题 1–2 条 / 多证据题 4–8 条，由 query 类型与实体数估计）；
  2. **置信度门槛**：低于阈值的不进结果；
  3. **分级返回**：高置信核心证据在前，低置信"对冲尾"在后并截断。
  合同上完全合法：官方只要求 `返回数量不得超过 top_k`，**没有下限**。
- **证据**：E5（K 过大 QA 退化）、E7（证据数 1.6–6.3 vs 预算 100）、ATM-Bench 的 `Joint@=QS×Recall@`（说明"召回够用即可，噪声要付代价"）。
- **预期增益**：**最高且最确定**。这是唯一"免费"的增益——不减功能，只减噪声。
- **工程量**：小（阈值 + 排序 + 截断，纯策略层）。
- **风险** 🔴：**如果 AML 的评分按"返回集合"算 F1 而非答案级**，那"少返回"的收益更大；但**如果官方期待"尽量多给"**，少返回可能丢证据。→ 两种情形都要在本地扫出最优点，不要拍脑袋。
- **必做**：本地扫 `K ∈ {5,10,20,50,100}`，画"K–QA/Recall/Precision"曲线，取平台期起点。

#### D5 跨模态分数校准与统一重排｜**降级 · 只做"绕行"，不做"校准"**

- **机制（原设想）**：文本向量与图像向量分数不可比 → 用统一跨模态 scorer 重排。
- **为什么降级**：E3 直接说明"图像向量主导检索更差"，最优解是**把检索统一到文本空间**（D1 的结构化文本），校准问题**被绕过而不是被解决**。再花力气做分数校准是在解决一个不该存在的问题。
- **保留部分**：短名单（top 20）用 **reranker** 重排（官方 ✅ 不限制）——这是唯一放开选型的一环，应把最强 reranker 用在这里。
- **工程量**：小（reranker 接入）。
- **风险**：跨模态 reranker 成本与延迟；需级联（见 §7 吞吐）。

#### D6 证据簇召回（多证据组合）｜**推荐 · 上限押注**

- **机制**：写入时按 `(时间窗, 地点, 事件)` 聚簇；检索时先召回 1–2 条**锚点**，再按簇扩展出一组证据，簇内做一致性去噪后一起返回。
- **证据**：ATM-Bench ~30% 需多证据、Hard 平均 **6.3 条**、跨证据时间跨度平均 **226 天**（最大 933 天）→ 单条 top-k 无法保证"同簇齐出"。
- **预期增益**：中高（只对多证据子集有效，但 Hard 集权重未知）。
- **工程量**：中（簇键设计 + 扩展逻辑 + 去噪）。**不建图**（E2），只用"同键分组"这种最轻的簇。
- **风险**：簇扩展会引入噪声，与 D4 的预算冲突 → 必须"先定预算、再按预算扩簇"。

### G 层：治理（什么时候不返回）

#### D7 拒答阈值与证据充分性判定｜**推荐 · 低成本加分**

- **机制**：独立于召回的"证据充分性"判定（query 所需槽位是否被覆盖、时间是否已失效、图文是否一致），不充分则返回 `{"data": []}`。
- **证据**：Mem-Gallery AR 占 **184/1711 = 10.8%**；E6 证明"强召回会把拒答题答错"（A-Mem、MuRAG 比 FIFO 差 5.8–7.2%）。官方红线亦要求 `不得把答案伪装为记忆记录` ✅。
- **预期增益**：中（约 1/10 的题）。
- **工程量**：小（规则 + 阈值）。
- **风险**：拒答阈值调高会伤其余 89% 的题 → **必须两个阈值分离**，并用本地集验证净增益。

#### D8 时间与状态治理（更新 / 冲突 / 失效）｜**推荐 · 折进 D1**

- **机制**：双时间轴（事件时间 / 记录时间）+ `valid_from/to` + `supersedes`；检索时按 `as_of` 过滤，冲突版本不同时进前 k。
- **证据**：ATM-Bench 的 MUT（记忆随时间更新）是核心特性之一；Mem-Gallery 的 KR 81 + CD 81（合计约 9.5%）"neither multimodal nor textual memory methods achieve satisfactory performance" → **是公开的空白区**。
- **工程量**：小（本质是 D1 的字段 + 过滤规则），故**不作为独立方向立项**。
- **风险**：时间抽取错误会误杀证据 → 只在能确定时写 `valid_to`，否则留空。

### X 层：使能与材料

#### D10 本地复现与代理评测｜**前提 · 最先做**

- **机制**：把 ATM-Bench harness 与 Mem-Gallery harness 跑通，建立统一的本地代理榜（Recall@k / Joint@k / F1 / AR 准确率 / 前 k 位置），在此之上标定 D4 的 K、D7 的阈值、reranker 选型。
- **证据**：两基准代码 MIT 且带 harness（§1）；`07` §五的"只有 1 次 Full"使本地信号成为唯一反馈渠道。
- **工程量**：中（环境 + 数据 + 适配 adapter）。
- **风险**：⚠️ HF 不可直连，需镜像；⚠️ AML 版本可能改编过，**只能用相对增益不用绝对分数**。
- **价值**：不直接加分，但它是"1 次 Full"唯一的保险，也是材料里"可复现性"的证明。

#### D9 声明式证据治理契约｜**推荐 · 材料层，不投工程**

- **机制**：把检索决策形式化成可声明的策略（属性 schema + 过滤阶段 + 排序键 + 阈值 + 模态采信序），场景只写声明不改代码；配套"检索决策日志"（可审计）。
- **证据**：官方公告 ⚠️ 要求参赛方**说明**"是否使用原图、OCR、caption，以及是否返回图片证据"（用户转述，官网未见同句）→ 平台**主动索取**这套策略；官方 4 条基本要求里"只返回证据""披露来源"也需要它。
- **预期增益**：间接（评审阅读面 + 复用价值 + `11` 的可复现性论证）。
- **工程量**：**小**——写 spec + 一份声明文件 + 日志格式，**不要写框架**。
- **风险**：容易过度工程化，吃掉本该给 D1/D4 的时间 → **硬性限时（≤ 1 天）**。

## 6. 推荐组合

### P0｜不做就没有有效提交（占 ~40% 工时）
1. **D10 本地复现**（Day 1–2，必须先做，否则后面全是猜）
2. **契约正确的 Add/Search 服务**：同步写入、`user_id` 过滤、`top_k` 上限、`data[]` 形态、鉴权、Health
3. **写入吞吐与降级**：≈800M tokens + 同步语义 = 吞吐是第一风险；必须能"降级但不断流"（见 §7）

### P1｜主攻（占 ~40%）
4. **D1 结构化记忆卡**（含 D8 的时间/状态字段）
5. **D4 自适应证据预算**（K 校准 + 分级返回）
6. **D2 多表示合一**

> 这三个是**乘法关系**而非并列：D4 的"必要证据数"要靠 D1 的字段估计；D2 去冗余后 D4 的预算才有意义；D1 让 D4 能在文本空间里做过滤。**单独做任何一个，增益都会打折。**

### P2｜押注 / 低成本加分（占 ~15%）
7. **D6 证据簇**（若本地显示多证据题占比高）
8. **D7 拒答阈值**（若本地 AR 准确率可提升且不伤其余类别）

### P3｜材料与叙事（占 ~5%，硬性限时 1 天）
9. **D9 治理契约（spec + 声明 + 决策日志）** + 开源仓库与固定 commit

### 明确不做
- 图链接记忆（E2）、图像向量主检索（E3）、复杂多模态架构（E4）、答案侧花招（无效且不合规）、区域级 grounding（13 天不够）、端到端训练（红线）、多赛道同时参赛（时间不够）。

**吞吐与延迟预算（必算，否则 Full 会超时）**
- Full 官方耗时 `0.5—2 天`；≈5,000 实例，且 `Streaming 可在多个增量节点检索同一道题` → 检索次数 > 5,000 次。

## 8. 市场方向：与赛题产物对齐的那一半

用户判断"多模态场景最多最大"——**方向成立，但需要拆开**，因为"应用多"不等于"这个赛题产物能卖"。

### 8.1 三个市场别混

| 市场 | 谁付钱 | TAM | 单价 | 与赛题产物的契合 | 可防御性 |
|---|---|---|---|---|---|
| ① **Agent 记忆层**（卖 API/SDK/自托管） | Agent 开发者、企业内部平台 | 大 | 中 | 🟢 **最高**——赛题评的就是"记忆层的 Search 契约" | 🟡 中（模型厂商正在吞并） |
| ② **垂直流程**（票据/工单截图/合同/医疗随访） | 企业 IT / 业务部门 | 中 | 高 | 🟡 中（需行业适配，但引擎可复用） | 🟢 高（合规与流程壁垒） |
| ③ **消费个人记忆**（相册/截图/剪贴板） | 个人 | **最大** | **最低** | 🟡 中（Mem-Gallery 正是此形态） | 🔴 低（Apple/Google 内置） |

### 8.2 竞品密度（⚠️ 二手来源，2026-10 Web 检索，未做 API 核验）

- **通用"记忆层"已经挤**：`memorylayer.ai`、`MemContext`、`memv.ai`、`ExoVault`、`memU`、以及一批低星仓库（`LATRACE-AI` ⭐4 等）。→ **"做个更好的通用记忆层"不是空位**，这与 `08` 的判断一致。
- **证据可追溯是新兴位**：`Hindsight` 的工程博客（2026-09）标题即"让事实引用它被读出的那张截图、且不编造证据"——**思路与我们一致但尚未形式化**。→ 窗口存在但正在关闭。
- **消费个人记忆已有人做**：`Orbit`（截图/剪贴板）、`PastPort`（屏幕记忆）、`LUCI`（本地屏幕记忆）、`Photo Agents`（"photographic memory"）。→ ③ 类是红海且单价低。

### 8.3 可防御性从哪来（这才是要回答的问题）

| 来源 | 是否成立 | 理由 |
|---|---|---|
| 更强的多模态模型 | ❌ | 平台/厂商直接给你，不构成壁垒（且 E3 说明它未必有用） |
| 更多数据 | ❌ | 无标注、无授权 |
| **证据治理：可审计、可声明、可复现** | ✅ | 赛题**主动要求披露**模态使用策略；企业场景要"能向审计解释为什么信这条"，通用厂商优化的是"好用"不是"可辩护" |
| **成本结构**（文本优先表示，而非全量 VLM） | ✅ | E3/E4 的结论恰好指向**低成本架构**：全量 VLM 理解是最贵的路线，而它并不更好 |
| 本地化 / 数据驻留 | ✅ | 自托管 + 私有部署是模型厂商结构性不愿做的事 |

### 8.4 建议定位

> **"可审计的多模态证据记忆层"**——卖引擎（①），用**一个**垂直场景（建议：工单/票据截图 或 个人图库回放）做证明，**不为场景改核心代码**（这正是 D9 声明层的市场价值：新增场景 = 写声明，不是改架构）。

**这也反过来解释了赛题选择的意义**：赛题把 Answer 固定、只评"你返回的证据"，本质上就是在考"**记忆层作为独立组件**"的能力。所以本次参赛产物天然就是 ① 的产品原型——这比"做一个记忆 App"更贴合赛事，也更贴合可防御性。

## 10. 一句话

> **多模态赛道的正确答案不是"更会看图的模型"，而是"更会写的记忆卡 + 更克制的手"**：把每条记忆写成结构化证据卡（D1）、把同一事实的多种表示合成一条（D2）、按估计的必要证据数返回而不是填满 100（D4）——这三条同时有两篇论文的消融证据、零合规风险、以及最强的市场复用性；而图记忆、图像向量主检索、复杂架构，都已被实验判为负收益。
> 在只剩 13 天、只有 1 次 Full 的前提下，**先把本地复现做出来（D10），再谈优化**——这是唯一能把"不可试错"变成"可以试错"的动作。
