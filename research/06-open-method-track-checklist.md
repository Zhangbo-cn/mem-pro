## 四、流程（7 步）✅

1. `提交准入申请` —— 选新 Key 或为已有 Key 增加版本；填联系人、系统版本、接口、鉴权、容量、运行限制；开源方法另附仓库与来源披露。
2. `完成 Key 绑定` —— 审核通过后签发 Leaderboard API Key；新增版本直接绑定到原 Key。
3. `运行公开 Smoke` —— 平台按现行同步规范执行 `Add → Search → Answer → Evaluate`。
4. `完成 Full 前置检查` —— 必须逐项勾选：`smoke 已通过、API 契约正确、运行说明完整，以及原创性披露和诚信承诺均已完成`。
5. `提交评测任务` —— 在 Evaluation 页面验证 API Key、选择已绑定版本、填唯一 **Run Label**。
6. `查看进度与审计状态` —— 页面显示阶段/进度/错误摘要；平台保留过程记录。
7. `查看结果与发布状态` —— 结果先仅对绑定 Key 可见；成功完成进入公榜资格校验与审核队列。

## 五、配额（稀缺资源，务必规划）✅

| 模式 | 配额 | 结果 | 公榜 |
|---|---|---|---|
| smoke | `每小时 1 次；本届每赛道最多 30 次` | 仅私有 | 不可发布 |
| **full** | **`本届每个 AML Key、每个赛道最多 2 次；第 2 次须在首次 Full 完成后 30 天发起`** | 优先私有 | 审核通过后发布 |

- ✅ `失败或取消的任务通过断点续跑恢复，不计为一次新的 Full。` + `重试和断点续跑保持同一 Add 的 request_id 与请求体。`
- **决策建议**：只有 2 次 Full，且第二次要等 30 天。因此**第一次 Full 必须尽早跑**（10 月下旬），否则第二次在截止（11-04）前无法发起。→ 见 `07-open-questions.md` 的"时间窗矛盾"分析。

## 六、四条基本要求（红线）✅ 原文

1. **`只返回记忆证据`** —— `Search 不得直接生成最终答案，也不得把答案伪装为记忆记录。`
2. **`保持样本隔离`** —— `不得跨 user_id、任务、样本或团队共享和检索评测记忆。`
3. **`披露来源与改动`** —— `复用论文、仓库或代码时，必须注明原作者、技术报告和全部方法改动。`
4. **`不得操纵评测`** —— `严禁硬编码、数据泄漏、提示词注入、人工实时答题、结果操纵和恶意刷榜。`

**取消资格风险** ✅：`重复提交相似或低质量代码、提示词注入、数据或结果操纵、恶意刷榜等行为，均可能取消参赛资格。`

## 七、公榜准入条件 ✅ 原文

> `结果必须来自成功完成的 full 模式固定套件，且所有评测任务均执行成功。统一回答模型、评测规范、pipeline code hash、dataset bundle hash 和题量记录必须完整，并与现行发布基线一致。结果不得重复提交，同时还需通过平台审核。`

**有效提交 5 项勾选** ✅ 原文：

- `✓ 材料完整` —— `参赛身份、系统版本和所需材料均完整、真实且可核验。`
- `✓ Smoke 通过` —— `Add / Search、鉴权和端到端链路符合现行接入协议。`
- `✓ Full 完成` —— `正式评测任务和所需评测项成功完成，没有缺失或重复结果。`
- `✓ 版本一致` —— `正式评测使用的代码、镜像或 API 与申报版本保持一致。`
- `✓ 复核通过` —— `版本、结果与合规状态通过主办方审核，方计为一次有效提交。`

## 八、数据处理责任（合规硬要求）✅ 原文

> `评测数据及其派生副本只能用于完成当前任务，不得用于模型训练、微调、产品分析、数据集重建或对外传播。请仅向必要人员开放访问权限，避免记录不必要的请求正文，并在任务完成后 30 天内删除相关数据；如需延长保留时间，必须事先获得我们的书面同意。`

**落地点**：不得把 AML 数据用于训练自己的 embedding/rerank 模型；日志避免留存完整请求正文；任务完成后 30 天内删除。

## 九、服务端技术合规要点 ✅

| 要求 | 原文 |
|---|---|
| HTTPS | `生产环境建议使用 HTTPS` |
| URL 无凭据 | `URL 中不得包含用户名、密码等凭据，也不得指向私有、回环或链路本地地址` |
| 错误信息不含密钥 | `参测接口应使用标准 HTTP 状态码，并返回便于排查问题且不含密钥的错误信息。` |
| 成功响应校验 | `即使 HTTP 状态码为 200，只要 Add 未返回 success=true 、三个 ID 未正确返回，或者 Search 未返回 data 数组、某条记录缺少 id / content ，当前阶段都会立即失败。` |
| 不静默截断 | `超量或存在非法条目会判为契约错误，不会静默截断后继续评分。` |
